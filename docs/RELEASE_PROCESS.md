# Публикация WoR Advisor

1. Изменить приложение в приватном `Jlapb-Main/wor-advisor`, зафиксировав точный исходный commit SHA.
2. Дождаться успешных тестов Windows/Linux, сборки PyInstaller и запуска сканера/OCR из автономного EXE в Actions.
3. Скачать артефакт `WoR-Advisor-windows-x64`. Сверить `source-commit.txt` и SHA-256 архива.
4. Создать GitHub Release с тегом версии, приложить ZIP и контрольную сумму; указать проверенный исходный коммит, ограничения данных и инструкцию установки.
5. После проверки опубликованного файла обновить `channels/stable.json`: version, download_url, sha256, source_commit и notes. Пользовательские данные не включаются в архив выпуска; исходные тестовые скриншоты в распространяемый пакет не входят.

Пример структуры release в канале: `{ "version": "0.1.0", "download_url": "https://github.com/Jlapb-Main/wor-advisor-updates/releases/download/v0.1.0/WoR-Advisor-0.1.0-windows-x64.zip", "sha256": "64 hex characters", "source_commit": "full SHA", "notes": "release URL" }`.

База игровых данных, версия приложения и версия установленного игрового клиента независимы. При ошибке синхронизации используется предыдущий локальный снимок.

Для публикации больших архивов доступен ручной workflow `Publish verified Windows release`. Он принимает краткоживущую ссылку на артефакт проверенного source Actions, ожидаемые SHA-256 и исходный коммит, сверяет вложенный ZIP, исключает пользовательские базы/тестовые скриншоты, публикует выпуск собственным GitHub Actions token этого репозитория и обновляет канал stable. Секреты личного аккаунта или приватного исходного репозитория ему не требуются. Опубликованный выпуск не перезаписывается: изменения выпускаются новой версией.
